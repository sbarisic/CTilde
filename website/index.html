Current implementation

One language, several execution models.

C~ keeps target choices explicit. Hosted applications can lean on native libraries and profile-guided optimization; firmware and freestanding programs provide the services their standard library needs; ESP32 can also load trusted C~ applications at runtime.

Managed ESP32 apps

Load, run, reclaim

Managed Module ABI 3 packages checked resident ELFs with optional Xtensa code overlays. Schema-3 references compile without provider source, and Runtime ABI 22 keeps managed calls cleanup-safe across returns and exceptions.

  • Checked managed imports
  • Independent state and heaps
  • Redirected process I/O

Tooling

Edit and debug in context

VS Code and Visual Studio understand .ctproj projects through the language server. The C~-aware debug adapter maps native execution back to source and supports hosted and ESP-IDF QEMU launch workflows.

  • Diagnostics and completion

Managed modules are ESP-IDF-only trusted native code. Checked cross-module calls now work; canonical descriptor substitution, shared generic implementations, and complete cross-module exception and resource handling remain in development.

03 / DEFER

Put cleanup beside acquisition.

A deferred call captures its arguments immediately and runs on every ordinary exit from the surrounding block, in LIFO order.

See deterministic cleanup →

using System.IO;

public static class Program
{
    [EntryPoint]
    public static void Main()
    {

08 / ASSEMBLY

Bind assembly operands explicitly.

GNU assembly uses declared input, output, read/write, constraint, and clobber clauses instead of implicit native state.

Read about inline assembly →
LANGUAGE.md 
[NoAlloc]
asm (
    in value as source,
    out("&r") result,
    ref accumulator,
    clobber("eax", "cc", "memory")
) {
    movl source, %eax
    addl %eax, accumulator
    movl %eax, result
}

09 / ASSEMBLY FUNCTIONS

10 / CONSTANT IMAGE DATA

Build native data before startup.

[ConstInit] evaluates restricted unmanaged values at compile time and emits immutable storage directly into the native image—without a module initializer or runtime edge.

Read about constant data →
MultibootHeader.ct 
[Packed(4)]
public readonly struct MultibootHeader
{
    public readonly uint Magic;
    public readonly uint Flags;
    public readonly uint Checksum;

    public MultibootHeader(uint magic, uint flags, uint checksum)
    {
        Magic = magic;
        Flags = flags;
        Checksum = checksum;
    }
}

[ConstInit]
[Used]
[Section(".multiboot")]
[Align(4)]
private static readonly MultibootHeader Header =
    new MultibootHeader(
        0x1BADB002u,
        0x00000003u,
        0u - 0x1BADB002u - 0x00000003u);

static assert(sizeof(MultibootHeader) == 12u);

11 / FREESTANDING QEMU

Own the image from first instruction.

The QEMU example combines immutable Multiboot data, assembly functions, a naked C~ entry point, explicit runtime lifecycle calls, and a regular string—without libc, a CRT, or a source assembly file.

Boot the complete kernel →
QemuFreestanding/Kernel.ct 
[Export("kernel_main")]
[NoAlloc]
[NoBlock]
public static unsafe int Main()
{
    Write("CTILDE_QEMU_OK\n");
    return 0;
}

[Naked]
[Export("_start")]
[NoAlloc]
public static unsafe asm void Start()
{
    cli
    cld
    movl $stack_top, %esp
    xorl %ebp, %ebp
    call ct_runtime_initialize
    call kernel_main
    movl %eax, %ebx
    call ct_runtime_shutdown
    movl %ebx, %eax
    outl %eax, $0xf4
1:
    hlt
    jmp 1b
}

F32x4 a = rays.Directions.LengthSquared();

F32x4 c = centerToOrigin.LengthSquared()
    - F32x4.Splat(radius * radius);

15 / MANAGED ESP32 APPLICATION

Run native modules as logical processes.

A .ctm application shares Runtime ABI 22 with firmware while keeping mutable statics, heap accounting, cancellation, copied mailboxes, console endpoints, child tasks, and an executable overlay window process-local. ManagedShell uses the same shell.ctm for UART, SSH, and one-command sessions; its development SSH modules add encrypted public-key channels and rooted SFTP without placing protocol code in firmware.

Explore ManagedShell →
ManagedShell/Modules/Hello/Program.ct 
using System.Diagnostics;
using System.Text;

[EntryPoint]
public static int Main(string[] args)
{
    Process current = Process.Current;
    byte[] payload;
    if (current.TryReceive(250u, out payload))
        Console.WriteLine(Encoding.UTF8.GetString(payload));
    return Process.IsCancellationRequested ? -1 : 0;
}
