Draft 0.25 experimental systems language

Familiar syntax.
Native systems.

C~ is a small, statically typed language with C#-style syntax. It compiles to deterministic GNU C23 and native programs—without the CLR.

C~
SOURCE → C23 → NATIVE

01

Predictable by design

Left-to-right evaluation, automatic reference counting, and block-scoped defer make ownership and cleanup explicit.

02

Native at the boundary

Deterministic GNU C23 output and explicit native contracts connect C~ to C libraries without a managed runtime.

03

Built for real targets

Use the same language for hosted programs, ESP-IDF firmware, controlled GNU/ELF freestanding images, and measured x86-64 Cosmopolitan APEs that run unchanged on Linux and Windows.

01 / INTRO

Start with types you already know.

C~ keeps familiar C#-style structure while producing a native program through its GNU C23 backend.

View the complete example →
Hello/Program.ct 
using System;

namespace Examples;

public static class Program
{
    [EntryPoint]
    public static void Main()
    {
        uint left = 2u;
        uint right = 3u;
        uint result = left + right;
        Console.WriteLine(result);
    }
}

Keep the object model familiar.

Classes support constructors, single inheritance, virtual members, overrides, properties, delegates, and explicit casts.

{
    protected int number;

    public Base(int number)
    {
        this.number = number;
    }

    public virtual int Read()
    {
        return number;
    }
}

public class Derived : Base
{
    public Derived() : base(4) { }

    public override int Read()
    {
        return base.Read() + 1;
    }

03 / DEFER

Put cleanup beside acquisition.

A deferred call captures its arguments immediately and runs on every ordinary exit from the surrounding block, in LIFO order.

See deterministic cleanup →
HostedIo/Program.ct 
using System;
using System.IO;

public static class Program
{
    [EntryPoint]
    public static void Main()
    {
        FileHandle image = File.Open(
            "image.ppm",
            FileMode.Create,
            FileAccess.Write);

        defer File.Close(image);
        Console.WriteLine("Rendering...");
    }
}

04 / NATIVE

Make native boundaries visible.

Attributes describe exact external symbols, transitive effect contracts, exported entry points, and interrupt-safe native boundaries instead of hiding semantic or ABI boundaries.

06 / EXCEPTIONS

Handle failure with ordinary control flow.

Typed catches, catch-all handlers, rethrow, and finally provide structured failure handling and cleanup.

{

}

{
    Console.WriteLine(error.Message);
}
catch (Exception)
{
    throw;
}
catch
{
    Console.WriteLine("fallback");
}
finally
{
    Console.WriteLine("cleanup");
}

08 / ASSEMBLY

Bind assembly operands explicitly.

GNU assembly uses declared input, output, read/write, constraint, and clobber clauses instead of implicit native state.

Read about inline assembly →
LANGUAGE.md 
[NoAlloc]
asm (
    in value as source,
    out("&r") result,
    ref accumulator,
    clobber("eax", "cc", "memory")
) {
    movl source, %eax
    addl %eax, accumulator
    movl %eax, result
}

09 / ASSEMBLY FUNCTIONS

Call assembly like an ordinary function.

Draft 0.25 gives raw GNU assembly a typed C ABI boundary. Parameters and results use explicit operands while effect attributes describe the opaque native work.

Read about assembly functions →
AssemblyFunctions.ct 
[NoRuntime]
[NoBlock]
public static unsafe asm void DebugWrite(char value)
    (in("a") value as output)
{
    outb output, $0xe9
}

[NoRuntime]
[NoBlock]
public static unsafe asm uint ReadPort()
    (out("a") result as value)
{
    inl $0xf4, value
}

DebugWrite('C');
uint status = ReadPort();

10 / CONSTANT IMAGE DATA

Build native data before startup.

[ConstInit] evaluates restricted unmanaged values at compile time and emits immutable storage directly into the native image—without a module initializer or runtime edge.

Read about constant data →
MultibootHeader.ct 
[Packed(4)]
public readonly struct MultibootHeader
{
    public readonly uint Magic;
    public readonly uint Flags;
    public readonly uint Checksum;

    public MultibootHeader(uint magic, uint flags, uint checksum)
    {
        Magic = magic;
        Flags = flags;
        Checksum = checksum;
    }
}

[ConstInit]
[Used]
[Section(".multiboot")]
[Align(4)]
private static readonly MultibootHeader Header =
    new MultibootHeader(
        0x1BADB002u,
        0x00000003u,
        0u - 0x1BADB002u - 0x00000003u);

static assert(sizeof(MultibootHeader) == 12u);

11 / FREESTANDING QEMU

Own the image from first instruction.

The QEMU example combines immutable Multiboot data, assembly functions, a naked C~ entry point, explicit runtime lifecycle calls, and a regular string—without libc, a CRT, or a source assembly file.

Boot the complete kernel →
QemuFreestanding/Kernel.ct 
[Export("kernel_main")]
[NoAlloc]
[NoBlock]
public static unsafe int Main()
{
    Write("CTILDE_QEMU_OK\n");
    return 0;
}

[Naked]
[Export("_start")]
[NoAlloc]
public static unsafe asm void Start()
{
    cli
    cld
    movl $stack_top, %esp
    xorl %ebp, %ebp
    call ct_runtime_initialize
    call kernel_main
    movl %eax, %ebx
    call ct_runtime_shutdown
    movl %ebx, %eax
    outl %eax, $0xf4
1:
    hlt
    jmp 1b
}
