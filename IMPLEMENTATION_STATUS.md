# Implementation status

Last reviewed: 2026-09-03

## Current state

C~ Draft 0.46 has one compiler path:

```text
.ct source -> full-fidelity syntax -> declarations -> immutable bound bodies and semantic maps -> flow/effect/target validation -> structured typed IR -> reachability/optimization -> unity or modular hosted/ESP-IDF/freestanding/Cosmopolitan GNU C23
```

The compiler library, CLI, and conformance runner target .NET 10. Draft 0.46 introduces Runtime ABI 19, `System.Storage`, an ESP-IDF SDSPI/BDL/FatFs/VFS component, process-owned filesystem services, mount-generation invalidation, and SD-first ManagedShell module resolution. Managed Module ABI 1 remains unchanged. The application-module slice includes deterministic metadata, a fixed `CTMOD` manifest, hidden module-local definitions, per-process mutable statics, FreeRTOS process startup, copied arguments and messages, cooperative cancellation, allocation accounting, structural dependency loading, immediate reverse release, stable 128-bit type fingerprints, and runtime descriptor registration/removal. Callable managed-library imports, authoritative canonical descriptor use, runtime-sized `ct_type_ops`, complete shared-code extraction, and process-level exception isolation remain in progress.

HostedIo divides the image into twelve horizontal rectangles and each worker fills its rectangle in linear scanline order. Its current accelerator is a deterministic flattened 16-bin SAH BVH with contiguous preorder nodes and reordered primitives, a depth cap of 32, fixed allocation-free scalar/packet traversal stacks, and read-only construction statistics. `object-midpoint-bvh` remains an explicit comparison baseline. The schema-2 SIMD benchmark identifies SAH as current, while the schema-1 BVH benchmark interleaves midpoint and SAH and gates identical checksums and traced-path census without a speedup threshold.

The compiler emits one C file by default or an immutable modular bundle containing `ctilde_types.h`, `ctilde_runtime_internal.h`, one `source_<hash>.h` declaration owner per source identity, the compatibility `ctilde_internal.h` umbrella, one runtime source, one source per reachable source identity, an entry/lifecycle source, a versioned symbol map, and an ESP-IDF CMake fragment. Implementations include only the runtime header, their owner header, and direct source-owner dependencies. Hosted, Cosmopolitan, and freestanding modular object keys hash each source's transitive generated-header closure, so body edits rebuild one object, declaration edits rebuild consumers, and shared layout/runtime edits invalidate affected units. Stack instrumentation settings and `.su`/`.ci` sidecars participate in caching.

`--stack-report <path>` and project `build.stackReport` opt into GCC `-fstack-usage -fcallgraph-info=su` analysis for hosted, WSL, freestanding, Cosmopolitan, and ESP-IDF GCC families. MSVC and Clang are rejected before compilation. `[StackUsage(n)]` is verified on body-bearing methods and trusted as a terminal bound on extern, native-import, and assembly-only methods. Schema-v1 reports resolve native symbols to C~ identities, retain lower bounds and unknown boundaries for incomplete graphs, verify complete `[TaskEntry]` headroom in bytes, and fail with `CT2226` for exceeded or unverifiable contracts after atomically writing the report. Runtime ABI 19 and debug metadata v3 are current.

`ctilde --run` rebuilds a project, releases the build lock, and launches its immutable host or WSL run configuration only after a successful build. The VS Code 0.15.0 **Run Project** command uses the same path.

## Runtime status

Managed objects use atomic, non-moving automatic reference counting. Compiler-generated retains and non-final releases use translation-unit-local inline paths and avoid repeated thread-state lookup; final release enters the existing attached-thread worklist. Public native retain/release functions still require attachment for every call, including null. Classes, contiguous arrays, contiguous dynamic strings, boxes, and nested reference-bearing structures release deterministically on the thread that atomically drops the last owned reference. Object allocation initializes an unassigned atomic identity hash, and the default hash assigns one stable nonzero value on first use without changing header layout. Type descriptors, vtables, the empty string, and literal string objects use portable `const` storage; ESP-IDF retains them in flash-backed read-only sections. Runtime-fault objects and mutable statics remain writable. Static strings and runtime-fault objects are immortal; static fields live until module finalization; cycles intentionally leak. Generated class, array, string, box, and structure drop helpers use a per-thread allocation-free LIFO worklist, so cascading destruction does not recurse on the C stack.

Recoverable runtime checks throw preinitialized `NullReferenceException`, `IndexOutOfRangeException`, `DivideByZeroException`, `InvalidCastException`, `OverflowException`, `ArgumentException`, or `OutOfMemoryException` objects. Raising them allocates nothing and preserves diagnostic code and source origin per thread. Runtime phase, attachment, ABI, reference-count, cleanup, and native-boundary violations remain panics; a configured panic callback runs before the default platform termination.

Each attached thread has independent `setjmp`/`longjmp` handlers, current-exception ownership, automatic cleanup records, and iterative release state. Only real `try` regions create exception frames. CFG liveness moves values into C-volatile durable storage only when they are modified after `setjmp` and remain live after a possible `longjmp`; this internal representation is separate from C~ acquire/release `volatile` fields. Ordinary `defer` uses direct automatic cleanup records and does not manufacture an exception frame.

The entrypoint calls `ct_runtime_initialize`, which attaches the primary thread, initializes fault singletons and the ABI-versioned module descriptor, and publishes ready. `ct_runtime_shutdown` requires secondary threads detached, finalizes static fields in reverse order, drains ARC work, and detaches the primary thread. Native-created threads use `ct_thread_attach` and `ct_thread_detach`; exports, callback trampolines, retain, and release reject unattached use. Source-created `Thread` workers use the same isolated runtime state and attach/detach lifecycle. Hosted builds use C thread-local storage, while ESP-IDF uses a configured FreeRTOS task-local-storage slot with deletion checking. ARC atomics protect lifetime only; sharing ordinary object state requires scalar `Atomic<T>`, acquire/release `volatile`, `Mutex`/`lock`, or another valid synchronization edge.

Draft 0.15 generics are whole-program monomorphized. The compiler interns each closed type and method by its canonical definition and substituted arguments, validates constraints before typed IR, and emits only reachable closed instances. Each closed reference-bearing layout receives its own ARC helpers and static storage. Interface references retain ordinary managed ownership; class conversion is allocation-free, structure conversion boxes, and concrete descriptors expose deterministic interface tables and dispatch slots. Open generics and runtime-backed interface, atomic, Thread, and Mutex values are rejected at native ABI boundaries.

The C ABI uses native target-width pointers and `nint`/`nuint`. Scoped native buffers use checked pointer-plus-length values, and scoped UTF-8 input retains its managed owner without allocating before flattening to `const char*`. Nominal opaque native handles carry lexical move-only ownership obligations. Stack allocation does not use the managed heap.

Hosted compilations add `Console.Read`, UTF-8 `Console.ReadLine`, and synchronous `System.IO` only when source uses that surface. Attached Windows consoles switch to UTF-8 before static initialization and restore their saved code pages after finalization; redirected handles remain byte-exact. Windows paths use validated UTF-8-to-UTF-16 conversion and Win32/CRT calls; POSIX uses validated UTF-8 paths. Move-only handles and explicitly disposed streams provide 64-bit seek/truncate, strict UTF-8 text, directory operations, sorted enumeration, and metadata. Unrelated hosted programs and all ESP-IDF output retain their earlier generated C.

## Draft 0.22 general effect contracts

`EffectRegistry` replaces the allocation-only registry with flag-based direct operations and call edges. `EffectAnalyzer` computes recursive effects after target pruning and closed generic construction. `[NoThrow]` and `[NoRuntime]` apply their documented implications without creating implied diagnostics; `[NoBlock]` remains independent.
